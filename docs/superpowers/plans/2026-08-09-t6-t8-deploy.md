# T6 + T8 — app.yaml + DABs git-source Deploy (dev) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy the Customer 360 FastAPI+React app to Databricks Apps as a git-source app via DABs (`bundle deploy` + `bundle run`) to a dev target tracking the `t5` branch on `fevm-test-jg`, with `app.yaml` wiring runtime config + OBO scopes.

**Architecture:** `app/app.yaml` sets the uvicorn command + static env; `requirements.txt` lists runtime deps; a DABs bundle (`databricks.yml` + `resources/app.yml`) declares a git-source app with `sql_warehouse` / `postgres` / `genie_space` resources and `user_api_scopes: [sql, dashboards.genie]`. The built SPA (`app/backend/static/`, force-committed on `t5` only) is served by FastAPI with no build step. Deploy is human-gated (real resources on fevm-test-jg).

**Tech Stack:** Databricks CLI v1.10.0 (DABs, Apps), FastAPI/uvicorn, Vite (local build → `backend/static/`), git.

## Global Constraints

- Profile is always explicit: `--profile fevm-test-jg`. Never hardcode the profile in `databricks.yml`.
- The deploy commands (`bundle deploy`, `bundle run`, `git-credentials create`) create/modify **real resources on fevm-test-jg** and require a GitHub PAT + workspace-admin toggles. The implementer MUST STOP and hand these to the user (or await explicit go-ahead) — never run them autonomously.
- Build output dir is **`app/backend/static/`** (vite `outDir`), ignored via `app/backend/static/` in `capstone-app/.gitignore`. `main.py` serves the SPA from `backend/static/`. There is NO `frontend/dist/`.
- App name `customer360-dev` (15 chars ✓ ≤26; lowercase+hyphens only).
- Verified values (do not re-derive): warehouse `e31f5efacda6d932`; dashboard `01f19331dc2e190cbba8dc3f1cbe1c26`; genie space `01f19331ffeb16119db5afb749349f4c`; catalog `test_jg_catalog`; PGHOST `ep-billowing-cake-d7ma4pcu.database.eu-central-1.cloud.databricks.com`; PGDATABASE `capstone_db`; LAKEBASE_ENDPOINT `projects/capstone-pg/branches/production/endpoints/primary`; **postgres db resource path** `projects/capstone-pg/branches/production/databases/db-dq3m-k807y4emil` (maps to pg db `capstone_db` — the resource id is a hash, NOT `capstone_db`); branch `projects/capstone-pg/branches/production`.
- git-source app resource shape (from DABs Apps reference): `git_repository: { provider: gitHub, url }` (both required) + `git_source: { branch, source_code_path }`; **no app-level `source_code_path`** (DABs rejects both).
- App-resource `resources` item shapes: `sql_warehouse: {id, permission: CAN_USE}`; `postgres: {branch, database, permission: CAN_CONNECT_AND_CREATE}` (NOT the legacy `database` key); `genie_space: {space_id, permission: CAN_RUN}`.
- Repo: `https://github.com/jogueber/gdc-apps-lakebase-capstone`. Deploy branch: `t5`.
- `bundle validate` is the authority on exact key nesting — fix config against its errors, don't fight it.

  - { name: "DASHBOARD_ID",      value: "01f19331dc2e190cbba8dc3f1cbe1c26" }
  - { name: "GENIE_SPACE_ID",    value: "01f19331ffeb16119db5afb749349f4c" }
  - { name: "CAPSTONE_CATALOG",  value: "test_jg_catalog" }

### Task 2: T8 — DABs bundle (databricks.yml + resources/app.yml)

**Files:**
- Create: `databricks.yml` (repo root)
- Create: `resources/app.yml`

**Interfaces:**
- Consumes: `app.yaml` (Task 1) as the app's runtime config at the git `source_code_path`.
- Produces: a `bundle validate`-clean git-source app definition named `customer360` (deployed name `customer360-dev`), tracking branch `t5`.

- [ ] **Step 1: Write databricks.yml**

Create `databricks.yml` at repo root:

```yaml
bundle:
  name: customer360

include:
  - resources/*.yml

variables:
  warehouse_id:      { default: "e31f5efacda6d932" }
  dashboard_id:      { default: "01f19331dc2e190cbba8dc3f1cbe1c26" }
  genie_space_id:    { default: "01f19331ffeb16119db5afb749349f4c" }
  catalog:           { default: "test_jg_catalog" }
  pg_uc_catalog:     { default: "test_jg_catalog" }
  git_repo_url:      { default: "https://github.com/jogueber/gdc-apps-lakebase-capstone" }
  git_branch:        { default: "t5" }

targets:
  dev:
    default: true
    mode: development
    workspace:
      host: https://fevm-test-jg.cloud.databricks.com
  prod:
    mode: production
    workspace:
      host: https://fevm-test-jg.cloud.databricks.com
    variables:
      git_branch: "main"
```

- [ ] **Step 2: Write resources/app.yml**

Create `resources/app.yml`:

```yaml
resources:
  apps:
    customer360:
      name: "customer360-dev"
      description: "Customer 360 — Acme Retail (capstone)"
      git_repository:
        provider: gitHub
        url: ${var.git_repo_url}
      git_source:
        branch: ${var.git_branch}
        source_code_path: capstone-app/app
      user_api_scopes:
        - sql
        - dashboards.genie
      resources:
        - name: sql-warehouse
          sql_warehouse:
            id: ${var.warehouse_id}
            permission: "CAN_USE"
        - name: database
          postgres:
            branch: "projects/capstone-pg/branches/production"
            database: "projects/capstone-pg/branches/production/databases/db-dq3m-k807y4emil"
            permission: "CAN_CONNECT_AND_CREATE"
        - name: genie-space
          genie_space:
            space_id: ${var.genie_space_id}
            permission: "CAN_RUN"
```

- [ ] **Step 3: Validate the bundle (this is the test)**

Run (from repo root):
```bash
databricks bundle validate -t dev --profile fevm-test-jg
```
Expected: validation passes (prints the resolved bundle, no errors). If it errors on a key (e.g. `genie_space` sub-shape, `postgres` fields, `git_source` vs `source_code_path`), FIX `resources/app.yml` against the exact message and re-run until clean. Do NOT deploy yet. Common fixes:
- "both git_source and source_code_path are set" → remove any app-level `source_code_path`.
- unknown field under a resource → correct per the error; the DABs schema is authoritative.

- [ ] **Step 4: Commit**

```bash
git add databricks.yml resources/app.yml
git commit -m "feat(t8): DABs git-source app bundle (dev target)"
```
(End the commit body with `Co-authored-by: Isaac`.)

- [ ] **Step 2: Un-ignore the build output**

Note: if a bare `!` negation doesn't take (git can't un-ignore if a parent dir is ignored — it isn't here, the entry is the dir itself), fall back to `git add -f capstone-app/app/backend/static` in Step 3. Verify with `git check-ignore`.
